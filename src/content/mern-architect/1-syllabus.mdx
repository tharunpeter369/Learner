# JavaScript Internals & Mastery — Architect Level

A deep, engine-up syllabus for engineers who must reason about *why* JavaScript behaves the way it does, make system-level decisions, and defend those decisions in senior/staff/architect interviews.

**Legend:** 🎯 = high-frequency interview hotspot · ⚙️ = engine/runtime internals · 🧠 = mental-model / spec-level depth

**Prerequisites:** Comfortable writing production JS, familiarity with ES2015+, basic understanding of the browser/Node runtime, and exposure to at least one large codebase.

**Outcome:** Ability to explain the engine's execution from source text to optimized machine code, diagnose memory and performance problems from first principles, design async-heavy and modular systems, and articulate trade-offs at the level expected of an architect.

- Engines in the wild: V8 (Chrome/Node), SpiderMonkey (Firefox), JavaScriptCore (Safari) — where they diverge
- Spec vs implementation: what's guaranteed vs what's an optimization detail

## [Module 1 — Engine Internals: Source to Machine Code](?tab=learn#module-1) ⚙️
- Pipeline overview: source → scanner/tokenizer → parser → AST → bytecode → JIT
- **Parsing:** eager vs lazy (pre-parsing), why function placement affects startup cost
- **Ignition** (V8 bytecode interpreter): what bytecode buys you
- **JIT tiers:** Sparkplug (baseline), Maglev (mid-tier), TurboFan (optimizing) 🧠
- **Hidden classes / Shapes / Maps** and how object structure drives optimization 🎯
- **Inline caches** (monomorphic → polymorphic → megamorphic) 🎯
- **Speculative optimization & deoptimization**: what triggers a bailout
- **Optimization killers**: changing object shape after creation, mixed-type arrays, `arguments` leakage, `try/catch` (historically), `delete` on hot objects
- Practical: read optimization/deopt traces (`--trace-opt`, `--trace-deopt`)

**Interview focus:** "Why is monomorphic code faster?", "What is a hidden class and how do you avoid breaking it?", "Walk me through what happens from parse to execution."

## [Module 2 — Memory Model & Garbage Collection](?tab=learn#module-2) ⚙️
- Stack vs heap; what lives where; value vs reference semantics 🎯
- Memory lifecycle: allocate → use → release
- **Generational GC:** young (Scavenger / Cheney's algorithm) vs old space
- **Mark-and-Sweep / Mark-Compact**; the tri-color marking abstraction 🧠
- Incremental, concurrent, and parallel GC (V8 Orinoco) — reducing main-thread pauses
- **Memory leaks** and how to find them: detached DOM nodes, forgotten timers/intervals, unbounded caches, closures capturing large scopes, lingering event listeners, accidental globals 🎯
- `WeakMap`, `WeakSet`, `WeakRef`, `FinalizationRegistry` — when and *why not*
- Tooling: heap snapshots, allocation timelines, three-snapshot leak technique, retained vs shallow size

**Interview focus:** "How does GC decide what to collect?", "Show me a closure that leaks memory.", "Why might a long-lived SPA's memory grow over time?"

**Output prediction / mental model**

- Closure-in-loop with `var` vs `let`
- `this` resolution across object methods, arrows, and detached references
- Coercion puzzlers (`==`, `+`, `[]`/`{}`)

**Implement from scratch**
- `bind`, `call`, `apply`
- `Promise` (A+), `Promise.all`, `allSettled`

- `curry`, `compose`/`pipe`, deep clone, deep equal
- Event emitter / pub-sub, simple Proxy-based reactive state
- `new` operator, `Object.create`, prototypal inheritance

**Explain the internals**
- Hidden classes & inline caches; deopt triggers
- Event loop (browser vs Node), micro/macrotasks
- GC generations and leak diagnosis
- ESM vs CJS resolution and live bindings

**System / architecture**
- Design a rate limiter / request scheduler with concurrency control
- Design caching with TTL and eviction (and why `WeakMap` helps)
- Diagnose a memory leak in a long-running SPA
- Move CPU-bound work off the main thread; choose worker strategy
